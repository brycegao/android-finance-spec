# UniApp + Vue3 + Vite 全局编码规范（V4.0 架构级 AI 执行纲领）

> ⚠️ **强制优先级声明**  
> 本文档为项目最高强制约束，CodeX 所有代码生成、代码审查、代码修改行为必须无条件严格遵守，优先级高于默认写法、通用语法及AI自身训练数据。任何偏离均视为违规产出。

## 零、AI 执行元指令（Karpathy 12 原则深度融合）

> 本章节专门为 CodeX 模型定义底层推理逻辑，优先级等同于语法规范。

1. **强制思维链（Chain of Thought）**：
   - 在处理任何业务需求前，**必须**在 `<thinking>` 标签内输出推理过程：拆解需求、识别现有可复用组件、定位跨端兼容风险、明确数据流向。
   - 禁止直接输出代码，必须先思考后生成。

2. **少样本遵循（Few-shot Alignment）**：
   - 生成新代码时，**必须**严格模仿项目现有 `/components` 或 `/pages` 中的高频写法模式（如：列表页的 `ref` 定义风格、请求调用的 `try-catch` 包裹模式）。
   - 若规范未明确细节，优先参照 `pages/index/index.vue` 的既定写法。

3. **明确输出格式（Explicit Output Structuring）**：
   - 最终交付必须严格区分 **“架构分析与推理”** 与 **“源码产出”**。
   - 代码必须包裹在标准 Markdown 代码块中，并标注具体语言类型（`vue`、`javascript`、`scss`）。

4. **显式假设与澄清（Explicit Assumptions）**：
   - 当业务需求描述存在模糊地带（如：列表加载方式未说明、异常边界未定义）时，**禁止盲目猜测**。必须列出具体假设清单（如：“假设列表采用分页加载，每页 20 条”），待确认后再落地代码。

5. **迭代修复协议（Iterative Debugging）**：
   - 若代码评审或编译报错，禁止直接重写全部代码。
   - 必须依据分级标准定位根因，按“🔴严重 -> 🟡一般 -> 🟠性能”顺序逐项修复，每次修复后需解释改动逻辑。

6. **零容忍“幻觉”依赖**：
   - 禁止臆造不存在于 `package.json` 或 `uni_modules` 中的插件、库或 API。
   - 若需引入新库，必须先明确提示并等待确认。

7. **像素级视觉对齐强制推理（UI还原核心）**
   - 生成任何页面/组件前，必须提取项目现有同类型页面视觉常量：字号、内外边距、圆角、阴影、边框粗细、色值，全部复用uni.scss全局变量，禁止手写十六进制色值、自定义rpx尺寸；
   - 思维链必须新增一段视觉拆解内容：列出当前页面所有UI元素尺寸，对标pages/index/index.vue同类卡片，逐一匹配padding、margin、border-radius；
   - 卡片、按钮、输入框、分割线必须1:1复用全局公共组件，禁止重新自定义样式。

8. **少样本视觉锁定规则**
   - 若提供设计稿截图/Figma链接，先逐行拆解视觉参数，记录所有UI尺寸，生成代码时严格一一对应，不做视觉美化、自主微调；
   - 无设计稿时，完全参照项目已有页面布局，布局结构、卡片高度、文字层级不得擅自改动。

9. **视觉输出校验自愈规则**
代码生成完成后，额外增加UI评审维度：
   1. 所有颜色是否使用uni.scss预设变量；
   2. 间距、圆角、字号是否和项目同类组件一致；
   3. 是否重复编写冗余样式，未复用全局components；
存在视觉不统一问题，自动迭代修正，直至完全对齐现有项目视觉体系。

## 一、基础技术框架约束

1. **语法范式**：全局强制使用 Vue3 `<script setup>` 语法糖，**禁止使用 Vue2 选项式 API、mixins、`export default {}`**。
2. **构建工具**：固定为 Vite，不切换 Webpack 等其他构建工具。
3. **响应式数据选型（强制统一）**：
   - 业务状态、接口数据、页面变量 **强制使用 `ref()`**，访问与修改必须通过 `.value` 操作；
   - `reactive` **仅允许定义硬编码静态常量配置对象**（编译期固定，如：表单验证规则、下拉选项枚举），**禁止解构、禁止直接整体赋值覆盖（`reactiveObj = {}`）、禁止用于接口返回数据赋值**；所有接口返回数据、动态页面状态一律强制使用 `ref`。
4. **TypeScript 工程化规则**：
   - **强制范围**：全局工具类（`/utils`）、接口请求与返回结构、核心业务实体（律师/律所/案例/用户）**必须编写完整 TS 类型声明（interface / type）**；
   - **可选范围**：页面/组件级别 TS 可选择性启用，但推荐复杂列表、表单页面使用；
   - **存放路径**：所有类型声明统一存放于 **`/types`** 目录；
   - **导出规范**：`/types/api.d.ts`、`/types/models.d.ts` 中的类型必须统一使用 `export` 导出；页面/工具使用统一通过 `import type { Lawyer, UserInfo } from '@/types/models'` 导入；**禁止在页面 `.vue`、工具函数内重复定义同名 interface**。
5. **环境区分与变量管理（严禁运行时平台判断）**：
   - 采用 Vite 内置 `.env` 环境文件（`.env.dev`、`.env.test`、`.env.prod`）+ `import.meta.env` 进行环境变量管理；
   - 域名、AppKey 等配置统一通过环境变量注入，**禁止硬编码**；
   - 平台差异化逻辑必须使用 UniApp 编译宏 `#ifdef` / `#endif` 进行静态条件编译，**严禁在运行时调用微信私有 API（如 `uni.getAccountInfoSync`）判断环境**，避免 App/H5 端白屏崩溃。

## 二、模板标签 & 路由跳转规范（强制）

### 2.1 基础标签约束
1. **禁用原生标签**：禁止使用 `div`、`span`、`img`、`a`、`p` 等 HTML 标签；
2. **强制使用 UniApp 原生组件**：
   - 布局容器：`<view>`
   - 纯文本展示：`<text>`（**所有文本内容必须包裹在 `<text>` 内**，禁止页面出现裸文本）
   - 图片资源：`<image>`
3. **模板缩进与格式**：统一使用 2 个空格缩进，标签必须闭合；
4. **列表渲染（`v-for`）**：必须绑定**业务唯一标识（类型为 `string | number`）** 作为 `:key`，**严格禁止使用 `index`**；若无业务 ID，需引入 `uuid` 生成唯一值，且禁止 `id` 为 `0` 或 `undefined`；
5. **显隐逻辑区分**：高频切换（如 Tab 切换）使用 `v-show`，条件性节点销毁重建（如权限判断）使用 `v-if`，**严禁在同一节点同时混用 `v-if` 与 `v-show`**；
6. **页面跳转组件红线**：**全局禁止使用 `<navigator>` 组件**，避免其在 H5 端编译为 `<a>` 标签导致 SPA 页面刷新白屏及复杂参数传递丢失问题。

### 2.2 路由跳转 API 规范（唯一合法方案）
所有页面跳转必须通过 `@click` 事件触发 UniApp 路由 API 实现：

| 跳转场景 | 强制使用 API | 说明 |
| :--- | :--- | :--- |
| 普通内页跳转 | `uni.navigateTo({ url })` | 保留当前页，跳转非 Tab 页 |
| Tab 底部栏切换 | `uni.switchTab({ url })` | 清空页面栈，**不携带自定义参数** |
| 返回上一页 | `uni.navigateBack({ delta })` | 返回指定层数 |
| 重定向（关闭当前页） | `uni.redirectTo({ url })` | 无法返回上一页时使用 |

**路径强制要求**：所有 `url` 必须使用 `pages.json` 中注册的**绝对路径**，格式以 `/pages/...` 开头，**禁止使用相对路径（如 `../`）**。

### 2.3 预加载平台兼容红线
`uni.preloadPage` **仅支持 App 端与微信小程序端**，H5 端不支持。使用前必须使用编译宏包裹：
```javascript
// #ifdef APP-PLUS || MP-WEIXIN
uni.preloadPage({ url: '/pages/lawyer/detail' })
// #endif
// #ifdef H5
// H5 端不执行预加载
// #endif
```

### 2.4 Tab 切换参数传递规范
Tab 页面间数据共享**统一使用 Pinia 全局状态**，**禁止使用 `localStorage` / `sessionStorage` 存储临时页面参数**，避免数据残留与污染。

## 三、样式规范（强制）

1. **单位分层使用规则**：
   - **强制 `rpx`**：页面宽高、字体大小、内外边距、圆角、阴影等视觉效果，**统一使用 `rpx`**，严禁使用 `px`；
   - **例外允许 `1px`**：分割线、边框线条（`border`）**允许固定使用 `1px`**，用于解决 iOS 视网膜屏下 `1rpx` 换算为小数像素导致细线条渲染丢失的问题；其余边框尺寸仍必须使用 `rpx`；
   - **设计稿基准统一**：项目统一使用 **750rpx 设计稿基准**，所有 UI 尺寸按 750 宽度设计稿标注开发，禁止按 375 宽度折算。
2. **样式隔离**：所有页面/组件的 `<style>` 标签**必须添加 `scoped`**，严禁全局样式污染；
3. **SCSS 全局变量注入（构建强制依赖）**：
   - 项目根目录必须包含 `uni.scss` 全局样式文件，定义设计系统变量；
   - **业务样式禁止直接硬编码十六进制色值**，必须调用全局变量；
   - **开发者无需在业务文件中手动 `@import`**，必须在 `vite.config.js` 中配置 `additionalData` 实现自动注入（配置片段见第六章）；
   - 核心颜色变量定义如下（贴合法律商务调性）：
     ```scss
     // uni.scss
     $primary-color: #1A2B4C;        // 沉稳商务深蓝（主色）
     $primary-light: #2C4A7C;        // 辅助亮蓝（按钮/高亮）
     $text-main: #1A2332;            // 正文深色
     $text-secondary: #6B7A8F;       // 辅助灰色文字
     $bg-page: #F5F7FA;              // 页面背景灰
     $border-color: #E8ECF1;         // 分割线浅色
     $font-size-base: 28rpx;         // 基础字号
     $font-size-lg: 32rpx;           // 大号字号
     ```
4. **布局策略**：优先使用 Flex 弹性布局，尽量避免写死固定宽高，适配多分辨率屏幕；
5. **Flex 兼容增强（App 端安卓老机型）**：Flex 容器必须同步添加 `display: flex; flex-wrap: wrap; box-sizing: border-box;` 基础属性，避免安卓低版本机型渲染偏移与布局塌陷；
6. **预处理器锁定**：全局统一使用 **SCSS** 语法，禁止使用 Less、Stylus 等其他方案。

## 四、图片专项规则（强制）

1. **懒加载**：所有网络图片必须开启 `lazy-load` 属性，优化长列表滚动性能；
2. **裁剪模式**：头像、卡片封面图统一设置 `mode="aspectFill"`，保证视觉统一且图片不变形；
3. **加载失败容错（核心：响应式驱动 + 死循环防护）**：
   - 图片 `:src` 必须绑定响应式变量（如 `:src="imgUrl"`）；
   - `@error` 事件回调内仅修改变量值（如 `imgUrl.value = defaultAvatar`），**禁止直接操作 DOM 元素（如 `e.target.src = ...`）**，此写法在微信小程序端永久失效；
   - **死循环防护（强制）**：定义全局常量标识 `HAS_FALLBACK`，图片加载失败后仅替换一次兜底图；若兜底图自身加载失败，**必须阻止后续 `@error` 触发**，避免无限重试导致页面卡死。实现示例：
     ```javascript
     const DEFAULT_AVATAR = '/static/images/default-avatar.png'
     const imgUrl = ref(remoteUrl)
     let hasFallback = false  // 单次加载周期仅降级一次
     
     const onError = () => {
       if (!hasFallback) {
         hasFallback = true
         imgUrl.value = DEFAULT_AVATAR
       }
     }
     ```
4. **统一占位图资源路径（强制）**：
   - 头像兜底：`/static/images/default-avatar.png`
   - 通用图文兜底：`/static/images/default-image.png`
5. **资源存放**：所有静态图片资源统一存放至项目 `/static` 目录，引用时使用项目根目录绝对路径（以 `/` 开头）。

## 五、网络请求 & 接口规范（强制）

1. **请求库锁定**：**仅基于 UniApp 原生 `uni.request` 封装**，严禁引入 `axios`、`luch-request` 等第三方请求库；
2. **统一封装**：全局请求工具必须存放于 `utils/request.js`，统一管理：基础域名、请求头、全局 Loading 计数器、状态码拦截、异常捕获与重试；
3. **接口状态码约定**：后端返回 `code === 200` 判定为业务成功，直接 `resolve(data)`；非 `200` 状态码强制 `uni.showToast` 弹出 `msg` 错误提示，并 `reject(error)`；
4. **Loading 生命周期（计数器实现标准）**：
   - `utils/request.js` 顶层导出一个全局 Loading 计数器变量 `loadingCount = ref(0)`（或普通 `let loadingCount = 0`，因请求模块非响应式上下文，推荐普通变量 + 闭包管理）；
   - 每次请求发起时 `loadingCount++`，请求完成（`complete`）时 `loadingCount--`；
   - 当 `loadingCount > 0` 时展示遮罩 `uni.showLoading`，当 `loadingCount === 0` 时关闭遮罩 `uni.hideLoading`；
   - 确保并发请求时 Loading 不会异常提前关闭或叠加多层；
5. **超时与断网重试机制（商务场景高可用）**：
   - 核心业务接口（如支付、下单、关键信息查询）若超时或网络异常，**自动重试 1 次**；
   - **交互策略**：首次超时保持 Loading 不消失，重试期间继续展示 Loading；若重试成功，正常关闭 Loading 并返回数据；若重试失败，关闭 Loading 并提示「网络开小差，请稍后重试」；
6. **域名管理**：禁止在业务代码或 `manifest.json` 中硬编码域名，全部通过 Vite 环境变量（`import.meta.env.VITE_API_BASE_URL`）注入。

├── config                 # 全局业务常量、枚举配置【强制新增】

### 6.2 命名规则
1. **文件/文件夹**：小写短横线命名法（kebab-case），例：`lawyer-card.vue`、`lawyer-detail`；
2. **变量/函数**：小驼峰命名法（camelCase），语义化命名，**禁止无意义单字母（a/b/c/data/temp）**；
3. **全局常量/环境变量**：大写+下划线格式（UPPER_SNAKE_CASE），集中管理。

### 6.3 注释规范（强制）
1. **文件/模块注释**：所有新增 `utils`、`stores`、`config`、`types` 等底层公共模块，文件顶部必须使用 JSDoc 块注释说明模块职责、输入输出边界、跨端注意事项。
2. **类/仓库注释**：所有 class、Pinia Store、组合式业务模块必须添加 JSDoc 注释，说明状态职责、持久化策略、外部依赖和调用场景。
3. **函数注释**：所有导出函数、异步函数、请求封装函数、复杂条件判断函数必须添加 JSDoc 注释，包含 `@param`、`@returns`，必要时补充失败边界。
4. **复杂逻辑注释**：重试、节流/防抖、平台条件编译、权限校验、Loading 计数器、图片兜底等跨端或边界逻辑必须在代码附近添加简洁说明。
5. **禁止冗余注释**：禁止为简单赋值、直观变量名、模板静态结构编写空洞注释；注释必须解释“为什么这样做”或“边界是什么”。

### 6.4 `vite.config.js` 强制配置基线（完整版）
```javascript
import { defineConfig } from 'vite'
import uni from '@dcloudio/vite-plugin-uni'

export default defineConfig({
  envDir: './',                     // 环境变量文件所在目录
  envPrefix: 'VITE_',               // 仅 VITE_ 前缀变量暴露给客户端
  css: {
    preprocessorOptions: {
      scss: {
        // 强制全局注入 uni.scss，业务样式禁止再手动 @import
        additionalData: '@import "@/uni.scss";'
      }
    }
  },
  plugins: [uni()]
})
```

## 七、组件通信规范（强制约束）

1. **父子组件**：父传子使用 `defineProps`，子传父使用 `defineEmits`，**禁止子组件直接修改 Props 值**；
2. **跨层级组件**：使用 `provide / inject` 进行依赖注入，避免层层传递；
3. **全局状态管理**：**彻底废弃 `bus` / `$emit` / `$on` 全局总线模式**，统一改用 **Pinia** 管理全局共享状态，保证数据流向清晰可追踪；
4. **脚手架前置校验**：项目必须包含 `/stores` 目录及 `stores/index.js` Pinia 初始化文件，`package.json` 必须包含 `pinia` 依赖，缺失时 CodeX 自动生成基础模板。

---

## 八、四端兼容性规范（红线）

代码必须同时兼容：**微信小程序、Android App、iOS App、H5 网页**。
1. **API 禁用**：禁止使用各端私有语法、私有样式、平台专属 API（如 `wx.`、`plus.`、`document.getElementById`）；
2. **平台差异化处理**：若无法规避底层差异，必须使用 UniApp 编译宏包裹（`#ifdef MP-WEIXIN` / `#ifdef APP-PLUS` / `#ifdef H5`），**严禁在运行时通过 `if (typeof wx !== 'undefined')` 等方式判断**；
3. **提前规避风险**：H5 跨域需配置 Vite 代理或后端 CORS；小程序需配置合法 request 域名；App 端需在 `manifest.json` 中声明原生权限。

---

## 九、可维护性 & 注释规范

1. **单一职责原则**：每个函数只做一件事，超长逻辑（超过 50 行）强制拆分为多个语义化子函数；
2. **注释强制覆盖场景**：
   - 全局工具函数、接口请求封装；
   - 复杂业务计算逻辑；
   - 跨端兼容处理块（`#ifdef`）；
   - 特殊业务规则（如：律师执业年限计算、案件状态流转）；
3. **注释格式要求**：必须包含中文说明、入参类型、返回值类型、特殊注意事项；
4. **架构预留**：列表项、卡片数据必须预留扩展字段（如 `extra`、`reserve1`），禁止写死无法迭代的硬编码判断。

---

## 十、视觉 & 交互约束

1. **整体调性**：商务简约，配色沉稳（深蓝/灰白），贴合法律服务平台的专业感与信任感；
2. **动效红线**：**禁止复杂动画、花哨转场、弹窗弹入弹出特效**，仅保留基础的点击反馈（`opacity` / `scale` 微变）、页面平滑跳转、图片预览；
3. **全栈统一**：同一类按钮（主按钮/次按钮/危险按钮）、弹窗（确认/取消）、列表卡片样式在全项目中必须保持视觉与交互高度统一。

---

## 十一、性能约束

1. **长列表优化**：必须结合图片懒加载，海量数据列表必须采用分页或滚动加载（上拉加载更多），**严禁一次性渲染超过 200 条以上的 DOM 节点**；
2. **响应式精简**：减少无效的 `watch` 深度监听，避免 `computed` 中产生高开销计算，合理使用 `shallowRef` 处理大对象；
3. **组件复用**：重复出现的 UI 区块（如律师卡片、案例条目）必须抽离为全局公共组件，避免重复编写相同样式与逻辑。

---

## 十二、路由补充规范

1. **绝对路径强制**：所有跳转路由必须使用 `pages.json` 内注册的绝对路径，以 `/pages/...` 开头；
2. **Tab 页特例**：底部 Tab 切换仅允许使用 `uni.switchTab`，该 API 会清空全部页面栈，且**无法携带自定义 URL 参数**，需通过全局状态（Pinia）传递数据；
3. **预加载平台限制**：`uni.preloadPage` 仅 App 端与小程序端支持，H5 端需通过编译宏隔离（详见 2.3 节）。

---

## 十三、CodeX 专属工作流与自愈协议（融合 Karpathy 迭代原则）

### 13.1 代码生成前置校验（脚手架初始化验收）
在执行任何业务页面代码生成前，CodeX 必须优先检查项目根目录是否包含以下必要文件与配置。若缺失，必须首先生成补齐：

1. `vite.config.js` 是否包含 `envDir`、`envPrefix` 及 `additionalData: '@import "@/uni.scss";'` 配置（**不仅校验文件存在，必须读取文件内容校验关键配置项**）；
2. 是否包含 `.env.dev`、`.env.test`、`.env.prod` 三套环境变量文件；
3. `/types` 目录是否存在，是否包含 `api.d.ts` 与 `models.d.ts`；
4. `/stores` 目录是否存在，是否包含 `index.js` Pinia 初始化文件；
5. `/config` 目录是否存在，是否包含 `enums.js` 与 `constants.js`；
6. `/static/images` 是否已放置 `default-avatar.png` 与 `default-image.png` 占位图（**物理文件存在校验**）；
7. `package.json` 是否包含 `pinia` 依赖（缺失时提示安装命令）；
8. `pages.json` 中首页路径是否正确，`globalStyle` 是否配置商务灰白背景。

### 13.2 代码生成规范（少样本与思维链要求）
1. **推理前置**：在产出 `<template>` 前，必须先分析项目现有同类页面（如列表页参考 `pages/index/index.vue`），确保新代码风格与现有代码高度一致；
2. 所有产出代码必须严格遵守本文档全部强制规范，格式整洁、缩进统一（2 空格）、分层清晰；
3. 生成代码时必须预留业务迭代扩展空间（如：预留插槽、预留接口字段），严禁写出不可维护的一次性逻辑。

### 13.3 代码生成后自动校验（自愈协议）
代码生成完成后，CodeX **必须自动执行一次完整规范评审**（按 13.4 标准）。若存在任何问题，CodeX 必须按“🔴严重 -> 🟡一般 -> 🟠性能 -> 🟢建议”的优先级顺序逐项修复。修复过程中，每次迭代需简要输出“根因分析”与“修复策略”，直至全部通过后方可交付。

### 13.4 代码评审分级标准（强制）
评审时必须逐条对照本文档规范进行检查，输出必须包含以下分级：

| 等级 | 标识 | 适用场景 | 处理要求 |
| :--- | :--- | :--- | :--- |
| **严重错误** | 🔴 | 编译报错、运行崩溃、四端兼容红线（禁用私有API）、DOM 直接操作、禁用标签使用（div/span/navigator）、硬编码域名、未加 `scoped`、缺失关键依赖 | **必须立即修复**，阻断交付 |
| **一般问题** | 🟡 | 工程化规范不达标（变量命名不规范）、类型/目录不合规、缺少注释、硬编码色值、未使用全局颜色变量、Pinia 状态使用不规范 | **建议修复**，合并前完成 |
| **性能阻塞** | 🟠 | 长列表一次性渲染超过 200 条、无效深度 `watch`、大对象未使用 `shallowRef`、未启用图片懒加载 | **建议修复**，合并前完成 |
| **优化建议** | 🟢 | 代码简化机会、布局兼容微调、交互体验微优化 | 供团队参考，不强制 |

**评审红线**：仅输出问题描述 + 可直接落地的修改方案，**禁止直接重写整段代码**，保留开发者自主思考空间。
